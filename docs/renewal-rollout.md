# 리뉴얼 운영 반영 계획 (2026-11-16)

테스트 환경(`redesign` 브랜치)의 새 디자인을 운영(donbuff.com)에 옮기는 방법. **한 번에 바꾸지 않고, 코드는 먼저 합치고 화면은 페이지별로 하나씩 연다.**

## 원리
- 운영(Vercel Production)은 `main` 브랜치를 배포한다. `redesign` 은 지금까지 `main` 과 합쳐지지 않은 별도 브랜치다.
- 새 디자인은 `web/redesign/pages.json` 의 `production` 목록에 주소가 있을 때만 운영에 보인다(지금은 비어 있음). 정적 페이지(메인·프롬프트·계산기·투자 성향)와 Next.js 회원 화면(`nextPages`)이 같은 목록을 쓴다.
- 그래서 **① 코드 합치기(화면 변화 거의 없음) → ② 목록에 주소를 하나씩 추가(그 페이지만 새 디자인)** 두 단계로 나눈다. 문제가 생기면 목록에서 주소를 빼고 다시 배포하면 즉시 이전 화면으로 돌아간다(Vercel 의 "이전 배포로 되돌리기"도 가능).

## 1단계: `redesign` → `main` 합치기 (PR 한 번)
- 지금 `main` 과 충돌 없음(운영에는 환율 자동 갱신 1건만 더 있음).
- 합치는 순간 운영에서 **바뀌는 것**(새 디자인이 아니라 코드·내용 변경):
  - 이용약관·개인정보처리방침 **본문**(기존 틀 그대로 새 문구가 보임) → 아래 3단계와 같은 날 하는 것을 권장
  - `/privacy.html` → `/privacy/` 영구 이동, 이전 원문은 `/archive/privacy-legacy-2026.html`(검색 제외)에 보관
  - 로그인 버튼: 성공 후 이동할 때까지 "로그인 중…" 유지, 소셜 로그인 "연결 중…" / 마이페이지·내 결과 이동 중 로딩 표시(기존 모양에서도 동작)
  - 가입 화면의 마케팅 동의 링크 → 개인정보처리방침의 해당 조항(`/privacy/#marketing`)
  - 검색 설정: `/archive/` 검색 제외, 사이트맵에서 `/privacy.html` 제거
- 바뀌지 않는 것: 메인·프롬프트·계산기·투자 성향·회원 화면의 **디자인**(목록이 비어 있어 기존 화면 그대로). 새 디자인 파일(`/redesign/…`)도 운영 빌드에는 포함되지 않는다.
- 합친 직후 확인(예: `node web/scripts/verify-routes.mjs https://donbuff.com`, 로그인·가입·결과 저장 한 번씩).

## 2단계: 페이지를 하나씩 열기 (`production` 목록에 추가)
영향이 작고 쓰임이 많은 순서. 한 번에 한 묶음씩 올리고, 각 단계마다 PC·모바일 확인 + GA4 이벤트 확인 후 다음으로 넘어간다.

| 순서 | 대상 주소 | 비고 |
|---|---|---|
| 1 | `/prompt/` | 가장 많이 쓰는 페이지, 즐겨찾기·로그인 게이트 연동 확인 |
| 2 | `/` | 메인 |
| 3 | `/calc/`, `/calc/why/`, `/calc/brokerage/`, `/calc/loan-prepay/`, `/calc/fx/` | 계산기는 noindex 유지(2026-11-26 즈음 해제 계획과 별개). 결과 저장·AI 게이트 확인 |
| 4 | `/invest-mbti/`, `/invest-mbti/paths/` | 검사 로직은 원본과 동일(비교 시험 통과). `/invest-mbti/paths/` 는 열 때 `site.ts` 의 `INDEXABLE_PATHS`(사이트맵)에도 추가 |
| 5 | `/join/`, `/login/`, `/signup/`, `/forgot-password/`, `/reset-password/`, `/welcome/`, `/onboarding/`, `/account/`, `/account/saved/`, `/pricing/` | 로그인·가입 전 과정을 운영에서 직접 한 번 끝까지 시험 |
| 6 | `/terms/`, `/privacy/` | 약관 v2 등록(아래 3단계)과 같은 날 |

주의: 목록 변경은 코드 배포가 필요하다(`pages.json` 수정 → PR → 합치기). 한 줄짜리 작은 PR로 나눠 올리면 되돌리기도 쉽다.

## 3단계: 약관·개인정보 v2 등록(재동의)
- 가입 시 동의한 문서는 DB `consent_documents` 의 `terms v1` / `privacy v1`(초안)이다. 새 문서를 `v2` 로 등록하면, `effective_at` 시각부터 기존 회원은 다음 로그인 때 **다시 동의** 화면을 본다. (DB 는 테스트·운영이 공유 → 등록 즉시 운영에 적용)
- 권장: `effective_at` 을 **공지 7일 뒤**(이용약관 제13조: 시행 7일 전 공지)로 예약하고, 공개(6번 단계)는 그 전에 한다. 화면의 시행일 문구(현재 `2026년 11월 1일`)도 그 날짜로 맞춘다(`terms.ts`, `privacy.ts`).
- 법률 검토는 공개 전에 받는다.

## 롤백
- 한 페이지만 문제: `production` 목록에서 그 주소만 제거 → 배포.
- 전체 문제: Vercel 에서 직전 배포로 되돌리기.
- 합치기 자체를 되돌려야 하면 해당 병합 커밋을 revert.
