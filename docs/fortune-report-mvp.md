# 새해 재테크 운세 — 상세 리포트(유료) MVP 설계안 (v0.1)

> 상태: 기획 초안. 구현 전 합의용 문서입니다.
> 가격·목표 수치·처리 시간은 일반 경험치 기반의 **가설**이며 실측 후 교정합니다.
> 법령·스토어 정책 항목은 이 문서 작성 시 원문을 대조하지 못했습니다. **[확인 필요]** 표시 항목은 시행 전에 반드시 확인합니다.
> 근거 자료: `reports/온라인 운세 서비스 현황.md`(수치 대부분 2차 출처·미검증), 원격 브랜치 `fortune-2027`의 `/fortune/` 구현(커밋 `eb31139`).

## 1. 목적과 검증할 가설

**목적:** 무료로 계산해 보여 주는 "기본 결과"는 그대로 두고, 더 깊은 해석을 원하는 사람이 **사람이 검수한 상세 리포트**를 돈 내고 받는지 가장 싸게 확인한다. 앱 개발·종합 운세 서비스 확장 여부는 이 결과로 결정한다.

| # | 가설 | 판단 지표 | 성공 기준(가설) |
|---|---|---|---|
| H1 | 기본 결과를 끝까지 본 사람 중 일부는 상세 리포트에 관심이 있다 | 결과 화면 → 신청 화면 진입률 | 3% 이상 |
| H2 | 관심 있는 사람은 실제로 결제한다 | 신청 화면 → 결제 완료율 | 10% 이상 |
| H3 | 사람 검수 리포트를 정해진 시간 안에 낼 수 있다 | 건당 처리 시간, 납기 준수율 | 건당 30분 이내, 납기 95% |
| H4 | 받은 사람이 만족하고 환불하지 않는다 | 만족도(5점), 환불률 | 4.0 이상, 환불 5% 이하 |
| H5 | 이 구조가 반복 구매·확장으로 이어질 수 있다 | 재구매·추가 주제 신청 의향 | 설문 30% 이상 |

**중단·확장 기준(가설):** 4주 운영 후 H2가 3% 미만이면 가격·문구를 한 번 조정해 2주 더 보고, 그래도 미달이면 접는다. H2·H3·H4가 모두 기준을 넘으면 앱·두 번째 주제를 검토한다.

## 2. 범위

**포함(MVP)**
- 결과 화면의 "상세 리포트 받기" 진입점, 신청 폼, 개인정보 동의, 웹 결제
- 신청 접수 → 담당자 작업 → 발송 → 만족도 조사까지의 운영 흐름
- 담당자용 작업 화면(최소: 신청 목록, 입력 정보 보기, 리포트 업로드/발송)
- 지표 이벤트, 환불 처리 절차

**제외(후속)**
- 앱 출시(웹 검증 후 판단), 완전 자동 리포트, 정기 구독, 두 번째 주제, 외부 역술인 마켓플레이스
- 기본 결과(무료)의 계산 방식 변경. 무료 단계는 지금처럼 **브라우저 안에서만 계산**한다.

## 3. 핵심 원칙

1. **무료 단계는 서버로 아무것도 보내지 않는다.** 현재 서비스의 강점(출생정보 미전송)을 지킨다.
2. **유료 신청 때만, 필요한 정보만, 동의받고 전송한다.** 신청하지 않은 사람의 정보는 서버에 남지 않는다.
3. **투자 권유로 보이지 않게 한다.** 리포트는 "재물운·소비·저축 습관 관점의 참고 해석"이다. 종목·상품·매수매도 언급을 금지하고, 금융 면책 문구를 넣는다.
4. **결과를 보장하지 않는다.** "정확히 맞힌다", "수익이 난다" 같은 표현을 쓰지 않는다. 오락·참고용임을 명시한다.
5. **사람이 마지막에 본다.** AI는 초안 작성까지만 맡고, 담당자가 계산값과 문장을 확인한 뒤 발송한다.

## 4. 사용자 흐름

```
/fortune/ 결과(무료, 브라우저 내 계산)
   └ 하단 CTA "상세 리포트 받기"  ← fortune_report_cta_click
        └ 리포트 소개·샘플·가격·납기·환불 안내  ← fortune_report_view
             └ 신청 폼(주제·고민·연락 이메일)  ← fortune_report_form_start
                  └ 개인정보 수집·이용 동의(별도 화면)
                       └ 결제(웹 결제창)  ← fortune_report_pay_start
                            └ 접수 완료 + 접수번호·예상 발송일  ← fortune_report_paid
                                 └ (담당자 작업)
                                      └ 이메일 발송 + 열람 링크  ← fortune_report_delivered
                                           └ 만족도 설문(D+1)  ← fortune_report_survey
```

### 4.1 화면별 요약

| 화면 | 내용 | 비고 |
|---|---|---|
| 결과 하단 CTA | "내 재물운, 사람이 한 번 더 풀어드려요" + 버튼 | 기본 결과 4개 탭 아래, 모바일은 하단 고정 CTA 재사용 검토 |
| 리포트 소개 | 구성(6장)·샘플 1장·납기·가격·환불·면책 | 샘플은 가상 인물 |
| 신청 폼 | 주제 선택(1~2개), 고민 한 줄(선택), 이메일, 이름(호칭) | 입력은 최소화 |
| 동의 | 수집 항목·목적·보유기간·제3자 제공 없음·거부 시 불이익 | 8.2 참고 |
| 결제 | 결제대행사 결제창 | 8.3 참고 |
| 접수 완료 | 접수번호, 예상 발송일, 문의 방법 | 이메일로도 발송 |
| 리포트 열람 | 이메일 링크(만료되는 서명 URL) 또는 PDF 첨부 | 8.2의 보관 기간 적용 |

### 4.2 입력 정보와 전송 범위

| 정보 | 용도 | 서버 전송 | 비고 |
|---|---|---|---|
| 양력 생년월일시·성별·출생지(시·군) | 담당자 재계산·검수 | 신청 시에만 | 한국 음력은 서버에서 다시 계산, 저장하지 않음 |
| 이메일 | 리포트 발송, 영수증 | 신청 시에만 | |
| 이름(호칭) | 리포트 호칭 | 신청 시에만 | 실명 불필요, 별명 허용 |
| 고민 한 줄 | 해석 초점 | 신청 시에만 | 선택 입력. 민감정보(건강·신용 등) 입력 금지 안내 |
| 계산 결과(명식·명반·차트) | 검수 기준 | **보내지 않음 권장** | 담당자 도구에서 같은 엔진으로 재계산해 불일치를 방지 |

> 계산 결과를 클라이언트 값 그대로 받으면 조작·오류가 섞일 수 있다. 입력값만 받아 서버(또는 담당자 도구)에서 같은 엔진으로 다시 계산한다. 이때 엔진 버전을 접수 건에 같이 기록한다.

## 5. 상품 설계

### 5.1 상세 리포트 구성안 (가설)

| 장 | 내용 | 작성 방식 |
|---|---|---|
| 1 | 한눈에 보는 2027 재물운 요약(키워드 3개, 종합 한 문단) | AI 초안 + 담당자 확정 |
| 2 | 사주: 재성 위치·세운(丁未)·대운 전환(2027-08 전환 여부) | 계산값 + 담당자 해석 |
| 3 | 자미두수: 재백·관록·전택·복덕궁, 유년 사화 | 계산값 + 담당자 해석 |
| 4 | 점성술: 2·5·8·10하우스, 2027 목성·토성 이동 | 계산값 + 담당자 해석 |
| 5 | 세 체계 교차 요약: 겹치는 신호·엇갈리는 신호를 구분해 보여 줌 | 담당자 작성(핵심 가치) |
| 6 | 소비·저축·일 습관 관점의 실행 제안 3가지, 주의할 시기, 면책 | 담당자 작성 |

- 분량은 PDF 8~12쪽 수준을 가설로 둔다.
- 5장(교차 요약)이 차별점이다. 무료 결과에서 이미 각 체계 데이터가 보이므로, 유료는 "그래서 무엇을 어떻게"를 담는다.
- 학파 기준(한국 음력 사용, 자미두수 엔진 기본 학파, 진태양시 등)은 부록에 한 줄씩 명시한다.

### 5.2 가격·납기 (가설, 확정 필요)

| 항목 | 가설 |
|---|---|
| 가격 | **정가 19,000원 / 출시 기념 12,900원** 중 A/B로 시험. 앞선 조사에서 확인된 상담 가격대는 5~10분에 5천~2만 원(2차 출처). 리포트는 서면·교차 해석이라 그보다 높게 잡음 |
| 납기 | 결제 후 **영업일 기준 3일 이내** 발송 |
| 수정 | 오탈자·계산 오류는 무료 재발송 1회 |
| 환불 | 8.4 참고 |

> 가격은 H2 지표와 담당자 시간당 원가를 같이 보고 정한다. 건당 처리 30분, 시급 3만 원이면 인건비만 1.5만 원이므로 12,900원은 적자다. **담당자 비용 구조를 확정한 뒤** 최종 가격을 정한다.

### 5.3 물량 관리

- 일 처리 한도(예: 10건)를 정하고, 한도 도달 시 "접수 마감, 다음 발송 가능일 안내" 문구를 보여 준다.
- 신년 시즌(연말~1월 말)에 신청이 몰릴 것을 가정하고, 납기를 시즌에는 5영업일로 늘리는 안을 준비한다.

## 6. 운영 흐름

| 단계 | 담당 | 도구 | 목표 시간 |
|---|---|---|---|
| 접수 확인 | 자동 | 이메일 + 관리자 알림 | 즉시 |
| AI 초안 생성 | 자동/반자동 | 기존 "통합 AI 프롬프트"를 서버에서 호출 | 수 분 |
| 계산값 검수 | 담당자 | 담당자 도구에서 재계산, 화면 대조 | 10분 |
| 문장 보정·5장 작성 | 담당자 | 문서 편집(템플릿) | 15~20분 |
| 발송 | 담당자 | 관리자 화면에서 파일 업로드 → 이메일 발송 | 5분 |
| 사후 | 자동 | D+1 만족도 설문 | — |

**품질 기준(체크리스트 초안)**
1. 접수된 입력과 리포트 속 간지·명반·하우스 값이 일치한다.
2. 12운성·장생12신 등 미검증 값은 쓰지 않는다(현재 `fortune-2027`과 동일 정책).
3. "재성 개수·주성 없는 궁"만으로 부유·빈곤·길흉을 단정하지 않는다.
4. 종목·상품·매수매도·수익 보장 표현이 없다.
5. 학파 기준과 계산 기준이 부록에 있다.
6. 출생일을 유추할 수 있는 정보(음력 날짜, UTC 일시)를 본문에 노출하지 않는다.

## 7. 지표와 이벤트

기존 이벤트(`fortune_tab`, `fortune_ai_open`, `fortune_ai_copy`, `fortune_share`, `fortune_map`)에 아래를 더한다. 이벤트명은 `docs/analytics-audit.md`의 규칙과 맞춘다.

| 이벤트 | 시점 | 주요 속성 |
|---|---|---|
| `fortune_report_cta_click` | 결과 CTA 클릭 | 위치(하단/고정), 현재 탭 |
| `fortune_report_view` | 소개 화면 노출 | 가격 안(A/B) |
| `fortune_report_form_start` / `_submit` | 신청 폼 시작/제출 | 선택 주제 |
| `fortune_report_pay_start` / `_paid` / `_fail` | 결제 | 결제수단, 실패 사유 |
| `fortune_report_delivered` | 발송 완료 | 처리 시간(분), 납기 준수 여부 |
| `fortune_report_survey` | 설문 응답 | 만족도, 재구매 의향 |
| `fortune_report_refund` | 환불 | 사유 |

개인정보(출생일시·이메일)는 이벤트 속성에 넣지 않는다.

## 8. 기술·법무 설계

### 8.1 아키텍처(최소안)

- 프론트: 기존 `web/redesign/pages/fortune*.js`에 CTA·신청 화면 추가. 결과 계산은 지금처럼 브라우저.
- 백엔드: 기존 Supabase(회원 설계서 `docs/member-platform-design.md`와 동일 스택)에 `fortune_report_orders` 테이블을 둔다. 웹훅으로 결제 결과를 받는다. **[확인 필요: 기존 회원 인프라 재사용 가능 여부]**
- 로그인: 비회원 결제(이메일+접수번호)를 기본으로 하고, 회원이면 내 리포트 목록에서 다시 본다(후속).
- 발송: 이메일 발송 서비스와 만료되는 서명 URL. PDF 첨부는 개인정보가 메일함에 남으므로 링크 방식을 권장한다.

**주문 테이블(초안)**

| 필드 | 설명 |
|---|---|
| id, order_no | 접수번호 |
| status | `paid` → `drafting` → `reviewing` → `delivered` → `closed`, 별도 `refunded` |
| input_enc | 출생 입력값(암호화 저장) |
| engine_version | 계산 엔진 버전 |
| email_enc | 이메일 |
| topics, note | 선택 주제, 고민 한 줄 |
| paid_at, due_at, delivered_at | 시각 |
| consent_ver | 동의 문서 버전과 동의 시각 |
| expire_at | 개인정보 파기 예정일 |

### 8.2 개인정보

- **수집 항목·목적·보유기간·거부권**을 별도 동의 화면에 고지하고 동의 이력(버전·시각)을 저장한다.
- **보유기간(제안):** 발송 후 30일(오류 재발송·문의 대응) 뒤 입력값 파기. 결제·거래 기록은 법정 보관 기간을 따른다. **[확인 필요: 전자상거래법상 보관 기간]**
- 출생정보와 이메일은 암호화 저장, 접근은 담당자 계정으로 제한하고 열람 로그를 남긴다.
- 만 14세 미만은 신청을 받지 않는다(연령 확인 체크). **[확인 필요: 개인정보보호법 요건 원문]**
- 외부 AI에 입력을 보낼 때는 이름·이메일을 빼고 호출하며, AI 제공자의 데이터 학습 제외 설정과 국외 이전 고지 필요 여부를 확인한다. **[확인 필요]**
- 개인정보처리방침에 이미 `[결제대행사 — 결제 기능 도입 시 추가]` 자리가 있다(`docs/design/legal-mockup-privacy.html`). 신청·결제·위탁 항목을 같이 갱신한다.
- 약관 6조 "유료 서비스" 환불 정책 자리를 채운다(`legal-mockup-terms.src.html`).

### 8.3 결제

- **1순위: 웹 결제**(국내 결제대행사 결제창). 앱 심사·인앱결제 수수료 이슈를 피하고 검증을 빠르게 한다.
- 앱 출시 시 같은 상품을 앱에서 팔려면 앱스토어/구글플레이의 결제 정책 분류(사람이 직접 만드는 서비스인지, 디지털 콘텐츠인지)와 수수료를 먼저 확인한다. **[확인 필요: 스토어 정책 원문, 국내 외부결제 허용 범위]**
- 결제 실패·중복 결제·웹훅 지연에 대비해 주문 상태 전이는 서버에서만 바꾼다.

### 8.4 환불·청약철회

| 상황 | 제안 정책(초안) |
|---|---|
| 작업 시작 전 | 전액 환불 |
| 발송 후 계산·내용 오류 | 무료 재발송 1회, 해결 안 되면 환불 |
| 발송 후 단순 변심 | 디지털 콘텐츠 제공 개시 사실을 신청 화면에 명시하고 철회 제한 안내 **[확인 필요: 전자상거래법 제17조 적용 및 표시 방식]** |

- 결제 화면에 "제공 개시 후 철회 제한" 안내와 동의 체크를 둔다.
- 사업자 요건(통신판매업 신고 등)과 정산·세무 처리는 시행 전에 확인한다. **[확인 필요]**

### 8.5 표시·광고

- 금지 표현: "정확히 맞힘", "수익 보장", "돈 번다", 종목·상품 추천.
- 필수 문구: 오락·참고용, 투자 권유·자문 아님, 개인정보처리방침 링크(기존 하단 문구 재사용).
- AI 초안을 쓴다는 사실과 "담당자가 검수한다"는 사실을 정확히 고지한다. 담당자 자격을 과장하지 않는다.
