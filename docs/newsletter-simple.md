# 최신 소식 발송 (간단 방식, v0.1)

회원이 적은 지금은 **개발 없이** Resend 대시보드로 직접 발송한다. 회원이 늘면 관리자 화면·자동 발송·사이트 안 소식함을 새로 설계한다.

## 발송 절차
1. **대상 뽑기** — Supabase SQL Editor(Database 모드)에서 `supabase/queries/marketing_recipients.sql` 실행 → Results 우측 위 `Export` → CSV.
   - 가장 최근 마케팅 동의가 "동의"인 회원만, 이메일 인증을 마친 탈퇴하지 않은 회원만 나온다. (읽기 전용 조회)
2. **Resend에 올리기** — Resend → Audiences → 오디언스(예: `돈버프 소식`) → Contacts → CSV 가져오기(`email` 열).
3. **작성·발송** — Resend → Broadcasts → 새 방송 → 발신 주소(인증된 donbuff.com), 대상 오디언스 선택, 제목·본문 작성.
   - 본문 맨 아래에 수신거부 링크 `{{{RESEND_UNSUBSCRIBE_URL}}}` 를 반드시 넣는다.
   - **내 주소만 있는 테스트 오디언스로 먼저 시험 발송**해 본 뒤 실제 오디언스에 보낸다.

## 법적으로 지킬 것 (광고성 정보, 정보통신망법 제50조 취지 — 법률 검토 필요)
- 수신 동의한 사람에게만 보낸다. (위 SQL이 보장)
- 제목 앞에 **`(광고)`** 를 붙이고, 본문에 보내는 사람(돈버프)과 연락처, **수신거부 방법**을 적는다.
- 밤 9시~아침 8시에는 보내지 않는다(별도 야간 동의가 없으면 금지).
- 동의 후 2년마다 수신 의사를 다시 확인해야 한다. (가입일 기준 목록으로 관리, 첫 확인 시기는 2028-11)
- 수신거부가 들어오면 지체 없이 중단한다.

## 수신거부 처리 (현재의 한계)
- 메일의 수신거부 링크는 **Resend에서만** 처리되고, 돈버프 DB의 동의 상태에는 반영되지 않는다. 회원이 내 계정에서 철회한 것은 DB에 남고 다음 1단계 SQL에서 자동 제외된다.
- 그래서 Resend 오디언스를 지우지 말고 계속 쓴다(수신거부한 연락처가 "거부" 상태로 남아야 한다). **첫 발송 전에 테스트 계정으로** 수신거부 → CSV 다시 가져오기 → 거부 상태 유지 여부를 확인한다. 유지되지 않으면 가져오기 전에 거부자를 따로 제외한다.
- 내 계정 → 마케팅 정보 수신 철회로 철회한 회원은 다음 가져오기 때 Resend에서 직접 삭제(또는 수신거부 처리)한다.

## 회원이 늘면 (후속 개발 후보)
- `/admin/news/` 작성·테스트 발송·전체 발송, 발송 이력, 수신거부 링크를 DB와 연동(동기화), 대량 발송 한도·비용 관리
- 사이트 안 "새 소식" 페이지, 카카오 알림톡
