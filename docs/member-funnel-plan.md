# 회원 전환 설계안 — 무엇을 열고, 무엇을 로그인 전용으로 할까 (v0.1)

> 상태: 기획 초안. 구현 전 합의용 문서입니다. 수치 목표는 일반 경험치 기반의 **가설**이며 실측 후 교정합니다.

## 1. 목표와 원칙

**목표:** 검색·공유로 들어온 방문자가 핵심 가치를 체험하고, 그 뒤에 "저장·동기화·개인화"가 필요하다고 느껴 **자연스럽게 가입**하도록 설계한다. 가입 데이터는 이후 커뮤니티와 B2B 구독의 기반이 된다.

1. **처음 체험하는 핵심 가치는 열어 둔다.** 계산 결과, 성향 테스트 결과, 프롬프트 열람·복사는 비로그인으로 쓴다. 유입(검색·공유)을 지킨다.
2. **가입 이유는 "결과를 본 뒤의 가치"로 만든다.** 저장, 기기 간 동기화, 개인화, 알림, 상세 리포트, 좋아요.
3. **강제 팝업은 쓰지 않는다.** 가치를 느낀 순간에 부드럽게 제안한다(넛지).
4. **기능을 막고 콘텐츠는 막지 않는다.** 기존 프롬프트 172개는 모두 공개를 유지한다.
5. **신규로 만드는 추가 기능은 로그인 전용으로 시작한다.** 서버에서 내려주는 방식으로 만들어 소스 보기로 우회할 수 없게 한다.

## 2. 확정된 결정

| # | 결정 |
|---|---|
| 1 | 기존 프롬프트는 **모두 공개**. 앞으로 **"신규 프롬프트" 메뉴**를 만들어 업데이트하고, 이 메뉴와 추가 기능은 **로그인 후** 사용 |
| 2 | 가입 후 **선택 정보**(관심분야, 직업군 등)를 받는다. 이후 B2B 마케팅 대상 선별에 쓴다. 선택 화면에 **"이런 게 편해요" 혜택 문구**와 **좋아요 같은 넛지**를 넣는다 |
| 3 | AI 분석 프롬프트 생성에 **비로그인 사용 한도를 두지 않는다** |
| 4 | 가입 전환 목표는 아래 7장의 가설 값으로 시작하고 2주 실측 후 확정 |

## 4. 1단계 상세

### 4.1 즐겨찾기 동기화 + 병합
- 비로그인: 지금처럼 이 기기에 저장(최대 5개). 3번째 저장 시 하단에 **작은 안내 바**: "로그인하면 즐겨찾기가 모든 기기에서 유지돼요."
- 로그인 시: 이 기기의 즐겨찾기가 있으면 **"N개를 계정으로 옮길까요?"** 로 병합 확인(중복 제거).
- 프롬프트 키는 기존 `idx`(예 `01/01`, 172개 모두 고유)를 그대로 쓴다.
- "최근 본 프롬프트"는 기기에만 둔다(동기화 대상 아님, 개인정보 최소화).

### 4.2 ♥ 좋아요 (넛지)
- 각 프롬프트에 ♥ + 좋아요 수(집계). 비로그인이 누르면 **가입 안내 시트**("로그인하면 좋아요가 저장돼요")를 띄운다. 막지 않고 닫을 수 있다.
- 좋아요 수는 "인기 프롬프트" 정렬의 근거가 되고, 이후 커뮤니티 활동의 씨앗이 된다.
- 즐겨찾기(★ 내 저장)와 좋아요(♥ 공개 집계)는 **분리**한다.

### 4.3 투자 성향 결과 저장과 상세 리포트
- 결과 화면에 "내 유형 저장하고 맞춤 프롬프트 받기" 카드. 저장하면 계정에 유형이 기록된다.
- 상세 리포트(약점 보완 프롬프트 세트, 추천 프롬프트 목록)는 회원에게 표시한다. 공유 카드는 비로그인도 사용한다(확산 유지).

### 4.4 계산 결과 저장·비교
- 결과 직후 "저장·비교" 버튼. 저장하면 `내 계정 > 저장한 결과`에서 시나리오를 비교한다.
- **금액 등 입력값은 민감하므로** 본인만 조회(RLS), 언제든 삭제 가능, 개수 상한(예: 50개).

### 4.5 가입 후 선택 정보 (프로필 완성)
- 가입 직후(약관 동의 다음) **1회 선택 화면**. 건너뛸 수 있고, 건너뛰면 `내 계정`에 **"프로필 완성" 카드**로 계속 안내한다.

| 항목 | 선택지 | 쓰임 |
|---|---|---|
| 관심 분야(복수) | 주식투자, 부동산, 절세, 재테크 루틴, 지출·저축, AI 활용 | 맞춤 프롬프트 우선 노출, 신규 프롬프트 추천 |
| 직업군(단일) | 일반 / 보험설계사·FC / 공인중개사 / 자영업 / 기타 | **B2B 대상 선별**, 맞춤 안내 |
| 경험 수준(단일) | 입문 / 실전 / 심화 | 프롬프트 난이도 추천 |

**넛지 문구(안):**
- 관심 분야: "관심 분야를 고르면 **맞는 프롬프트를 먼저 보여드려요**"
- 직업군: "직업군을 알려주시면 **업무에 도움 되는 도구**가 나오면 먼저 알려드려요"
- 진행 표시: "프로필 완성 33% → 신규 프롬프트 맞춤 추천이 열려요"
- 마케팅 수신 동의와 **분리**한다. 선택정보 입력은 마케팅 동의를 전제로 하지 않는다.

### 4.6 신규 프롬프트 메뉴 (로그인 전용)
- 경로 `/prompts/new/`. 새 앱(서버 렌더링)에서 만들고, **프롬프트 본문은 DB에 두어 로그인한 회원에게만 내려준다.**
- 비로그인에게는 **제목·분야만 보이는 티저**와 "로그인하고 전체 보기". 본문은 서버에서 보내지 않는다.
- 기존 `/prompt/`의 "신규" 카드(현재 네이버 블로그 글 링크)는 티저 역할로 연결하거나 교체한다.
- 헤더·메뉴에는 자물쇠 표시와 함께 항목을 추가한다(기존 `auth-nav.js` 확장).

## 5. 데이터 모델 초안 (1단계)

모든 테이블은 RLS를 켜고 **본인 행만** 접근 가능(좋아요 집계만 공개 함수로 노출).

| 테이블 | 주요 컬럼 | 비고 |
|---|---|---|
| `member_preferences` | `user_id`(PK), `interests text[]`, `occupation text`, `experience text`, `completed_at` | 선택정보. 운영 조회는 관리자 전용 |
| `user_favorites` | (`user_id`, `prompt_key`) PK, `created_at` | 즐겨찾기 동기화 |
| `prompt_likes` | (`user_id`, `prompt_key`) PK, `created_at` | 집계는 `prompt_like_counts` 함수/뷰로 공개 |
| `saved_results` | `id`, `user_id`, `tool`, `title`, `inputs jsonb`, `result jsonb`, `created_at` | 개수 상한, 삭제 가능 |
| `mbti_results` | `user_id`, `type_code`, `taken_at` | 재검사 비교용 |
| `new_prompts` | `id`, `title`, `category`, `level`, `ai`, `body`, `published_at` | **로그인 회원만 SELECT** (RLS), 제목·분야는 티저용 공개 뷰 |
| `profiles.signup_source` | 컬럼 추가 | 어느 유도 위치에서 가입했는지(분석용) |

## 6. 측정 (GA4 이벤트)

| 이벤트 | 파라미터 | 목적 |
|---|---|---|

## 7. KPI (가설, 초기 3개월)

| 지표 | 목표 | 비고 |
|---|---|---|
| 신규 방문자 → 가입 | **1.5%** (도전 3%) | 콘텐츠·도구 사이트의 일반적 0.5~3% 범위의 중간. **2주 실측 후 확정** |
| 유도 노출 → 클릭 | 5% 안팎 | 위치별 비교용 |
| 클릭 → 가입 완료 | 30% 이상 | 소셜 로그인으로 마찰을 낮춘다 |
| 선택정보 입력률 | 50% | 넛지 효과, B2B 선별 가능성 |
| 가입 후 7일 내 재방문 | 20% 이상 | 의미 있는 회원으로 이어지는지 |

## 8. 기술·법무 유의
- **콘텐츠 게이팅은 서버가 내려주는 데이터에만 유효하다.** 정적 HTML 안의 내용은 가려도 우회된다. 그래서 기존 172개는 공개, 신규는 서버 데이터로 만든다.
- 선택정보(직업군 등)는 **수집 목적을 약관·개인정보처리방침에 명시**해야 한다. 마케팅 수신 동의와 분리한다.
- 계산 결과 저장은 금액 정보를 담으므로 **최소 저장, 본인만 조회, 삭제 가능**이 원칙이다.
- B2B 마케팅 활용 전에 **수신 동의(정보통신망법)** 와 **개인정보 제3자 제공 여부**를 전문가와 확인한다.
- 환율 알림 등 알림은 **마케팅과 별도의 "서비스 알림" 동의**로 받는다.
