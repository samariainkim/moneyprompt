# 회원 전환 설계안 — 무엇을 열고, 무엇을 로그인 전용으로 할까 (v0.3)

> 상태: 기획 초안. 구현 전 합의용 문서입니다. 수치 목표는 일반 경험치 기반의 **가설**이며 실측 후 교정합니다.
> v0.2 변경: ♥ 좋아요 제거, 신규 프롬프트 메뉴는 현행 유지, 즐겨찾기·AI 프롬프트 생성을 로그인 전용으로 변경, 월 방문자 목표 1만 명 반영.

## 1. 목표와 원칙

**목표:** 검색·공유로 들어온 방문자가 **기본 결과를 무료로 체험**하고, "더 깊은 내용(AI 프롬프트 생성, 즐겨찾기 등)"이 필요하다고 느낄 때 **로그인(가입)** 하도록 설계한다. 가입 데이터는 이후 커뮤니티와 B2B 구독의 기반이 된다.

1. **기본 결과는 열어 둔다.** 계산 결과, 성향 테스트 요약 결과, 프롬프트 열람·복사는 비로그인으로 쓴다. 유입(검색·공유)을 지킨다.
2. **심화 기능은 로그인 전용이다.** AI 프롬프트 생성, 즐겨찾기, 결과 저장·비교, 상세 리포트.
3. **로그인했다가 돌아왔을 때 입력과 결과가 그대로 있어야 한다.** (4.3 참고. 이게 깨지면 이탈이 크다.)
4. **강제 팝업은 쓰지 않는다.** 기능을 누른 순간에만 가입을 제안한다.
5. 기존 프롬프트 172개는 모두 공개를 유지한다.

## 4. 1단계 상세

### 4.1 즐겨찾기 (회원 전용)
- 비로그인: ★ 버튼은 보이되, 누르면 **가입 안내 시트**("즐겨찾기는 로그인하면 쓸 수 있어요. 모든 기기에서 유지돼요"). 닫을 수 있다.
- **기존 방문자 보호:** 지금 이 기기에 저장된 즐겨찾기(localStorage)가 있으면, 삭제하지 않고 보관한다. 로그인할 때 **"이 기기의 즐겨찾기 N개를 계정으로 옮길까요?"** 로 이관한다. 비로그인 상태에서는 읽기만 되고 추가·수정은 로그인 안내.
- 프롬프트 키는 기존 `idx`(예 `01/01`, 172개 모두 고유)를 쓴다. "최근 본 프롬프트"는 현재처럼 이 기기에 둔다(변경 없음).

### 4.2 AI 프롬프트 생성 — 로그인 게이트 (투자 성향·계산기)
- 기본 결과(숫자, 유형 요약)는 그대로 보여준다.
- **"AI 분석 프롬프트 만들기"** 를 누르면 비로그인은 가입 안내 시트(혜택: "내 결과로 AI에게 바로 물어볼 프롬프트를 만들어 드려요"). 로그인하면 **같은 화면으로 돌아와 바로 생성**한다.
- 맛보기: 안내 시트에 **프롬프트의 첫 몇 줄을 흐리게 미리 보여** 가치를 느끼게 한다(전체는 로그인 후).
- 회원은 생성 횟수 제한 없음.

### 4.3 로그인 후 상태 복원 (필수)
- 로그인으로 보내기 전에 **입력값·결과·퀴즈 응답을 브라우저에 임시 저장**(sessionStorage/localStorage)하고, 로그인 후 `next`로 돌아오면 복원해서 **이전 화면과 같은 상태**로 이어간다.
- 소셜 로그인은 외부 주소를 거쳐 돌아오므로 이 복원이 특히 중요하다. 투자 성향은 이미 진행 상태를 저장하는 구조라 재사용한다.

### 4.4 투자 성향 결과 저장·상세 리포트
- 결과 화면 "내 유형 저장하고 맞춤 프롬프트 받기". 저장하면 계정에 유형이 기록된다. 상세 리포트(약점 보완 프롬프트 세트)는 회원 전용. 공유 카드는 비로그인도 사용(확산 유지).

### 4.5 계산 결과 저장·비교
- 결과 직후 "저장·비교". `내 계정 > 저장한 결과`에서 시나리오를 비교한다.
- 입력 금액 등은 민감하므로 **본인만 조회(RLS), 삭제 가능, 개수 상한(예: 50개)**.

### 4.6 가입 후 선택 정보 (프로필 완성)
가입 직후(약관 동의 다음) **1회 선택 화면**. 건너뛸 수 있고, 건너뛰면 `내 계정`에 **"프로필 완성" 카드**로 계속 안내한다.

| 항목 | 선택지 | 쓰임 |
|---|---|---|
| 관심 분야(복수) | 주식투자, 부동산, 절세, 재테크 루틴, 지출·저축, AI 활용 | 맞춤 프롬프트 우선 노출 |
| 직업군(단일) | 일반 / 보험설계사·FC / 공인중개사 / 자영업 / 기타 | **B2B 대상 선별** (필요시 추가) |
| 경험 수준(단일) | 입문 / 실전 / 심화 | 난이도 추천 |

**혜택 문구(안):**
- 관심 분야: "관심 분야를 고르면 **맞는 프롬프트를 먼저 보여드려요**"
- 직업군: "직업군을 알려주시면 **업무에 도움 되는 도구**가 나오면 먼저 알려드려요"
- 진행 표시: "프로필 완성 33% → 맞춤 추천이 열려요"
- 마케팅 수신 동의와 **분리**한다.

## 7. KPI (가설)

**1차 목표: 월 방문자 1만 명.** 현재 실측 값은 이 문서 작성 시점에 확인하지 못했다(GA4 필요).

| 지표 | 목표 | 월 1만 명 기준 환산 |
|---|---|---|
| 방문자 → 가입 | **1.5%** (도전 3%) | 월 **150명** (도전 300명) |
| 가입자의 선택정보 입력률 | 50% | 월 75명 |
| 가입 후 7일 내 재방문 | 20% 이상 | 월 30명 |

(방문자 수 기준으로 단순 환산. 신규 방문자 비율에 따라 실제 가입자 수는 달라진다.)

**보호 지표(가드레일):** 심화 기능을 로그인 전용으로 바꾸면 도구 사용과 공유가 줄 수 있다. 도입 전후로 다음을 비교한다.
- `calc_result` → AI 프롬프트 생성 **시도율**(로그인 안내 클릭 포함)
- 투자 성향 완료율과 **공유율**
- 이 값이 도입 전 대비 **크게 하락하면**(예: 30% 이상) 안내 방식이나 게이트 범위를 조정한다.

## 8. 기술·법무 유의
- **정적 페이지의 프롬프트 생성은 브라우저에서 실행되는 코드다.** 이번 1단계는 **화면 단의 로그인 게이트(소프트 게이트)** 이므로, 소스 보기·개발자 도구로 우회할 수 있다. 가입 유도가 목적이라 1단계는 이 수준으로 충분하다고 본다.
- 우회를 막아야 한다면 **프롬프트 생성 로직을 서버로 옮기는 하드 게이트**가 필요하다(프롬프트 생성 코드는 Node에서 테스트되는 구조라 이전 가능). 우회가 문제가 될 때 2단계에서 한다.
- 즐겨찾기를 회원 전용으로 바꾸면 **지금 무료로 쓰던 기능이 사라지는 것**이다. 4.1의 보관·이관 안내로 불만을 줄인다.
- 선택정보(직업군 등)는 **수집 목적을 약관·개인정보처리방침에 명시**해야 한다. 마케팅 수신 동의와 분리한다. B2B 마케팅에 쓰려면 수신 동의(정보통신망법)와 제3자 제공 여부를 전문가와 확인한다.
- 계산 결과 저장은 **최소 저장, 본인만 조회, 삭제 가능**이 원칙이다.

### 구현하면서 정한 것
- **선택정보 화면은 가입 안내 시트에서 온 로그인에는 건너뛴다.** 하려던 일(프롬프트 생성 등)을 먼저 이어가고, 다음 일반 로그인 때 한 번 묻는다. 건너뛰거나 입력하면 다시 묻지 않는다.
- **선택정보·즐겨찾기 테이블이 아직 없으면(마이그레이션 적용 전)** 로그인을 막지 않고 해당 단계를 건너뛴다.
- 안내 시트의 **프롬프트 미리보기**: 투자 성향은 내 결과 기반 프롬프트의 앞부분 일부, 계산기는 도구별 **예시 문구**(시트에 "미리보기"로 표시, 실제 생성 프롬프트가 아님).
- 비로그인 상태의 투자 성향 결과 화면에서는 프롬프트 **전문을 화면(DOM)에 남기지 않고** 앞 5줄만 남긴다.
- 기존 방문자의 **기기 즐겨찾기는 지우지 않고** 읽기만 가능하게 두며, 로그인 시 계정으로 옮길지 묻는다(나중에 → 7일 뒤 다시).

### 한계
- 게이트는 **화면 단(소프트) 게이트**다. 개발자 도구로 우회할 수 있다. 우회를 막으려면 프롬프트 생성 로직을 서버로 옮겨야 한다(2단계).
- 게이트는 **Vercel 빌드 결과물에만** 적용된다. `donbuff.com`(GitHub Pages)은 도메인 전환 전까지 지금처럼 모두 열려 있다.
