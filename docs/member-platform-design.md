# 돈버프 회원 플랫폼 설계안 (v0.1 초안)

## 1. 목표와 범위

| 단계 | 내용 | 상태 |
|---|---|---|
| 1차 | 회원가입·로그인, 내 계정, 동의 이력, 요금제/구독 DB 틀 | 이 문서의 범위 |
| 2차 | 결제(구독) 연동 | 사업자등록·PG 심사 후 |
| 3차 | 게시판·댓글·신고·관리자 | 회원 구조 위에 확장 |
| 4차 | B2B(FC·공인중개사) 사업자 프로필·전용 기능 | 수요 검증 후 |

## 2. 기술 스택

- **앱**: Next.js (App Router) + TypeScript
- **DB·인증**: Supabase (서울 리전), 접근은 RLS로 제어
- **배포**: Vercel (GitHub 연동, PR 미리보기)
- **결제**: 토스페이먼츠 또는 PortOne (2차)
- 기존 정적 페이지(`/calc`, `/fee`, `/prompt`, `/invest-mbti`)는 `public/`에 그대로 두어 URL·SEO 유지

## 3. 환경변수

| 이름 | 공개 여부 | 용도 |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | 공개 | 프로젝트 URL |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | 공개 | 브라우저용 키 (RLS로 보호) |
| `SUPABASE_SECRET_KEY` | **비공개** | 서버 전용(회원 탈퇴 처리, 결제 웹훅). 저장소·채팅에 올리지 않음 |

## 4. 데이터 모델

```
auth.users (Supabase 관리)
   └─ profiles            1:1  닉네임, 역할(member/business/admin), 탈퇴 표시
        ├─ user_consents  1:N  동의 이력 (append-only)
        │     └─ consent_documents  약관 종류·버전
        └─ subscriptions  1:N  구독 상태 (쓰기는 서버만)
              └─ plans    요금제
```

### 핵심 설계 결정

1. **동의는 UPDATE하지 않고 이력으로 쌓는다.** 마케팅 수신 철회도 `agreed=false` 행을 추가한다. 나중에 아웃바운드 마케팅이나 분쟁 때 "언제 어떤 버전에 동의했는지" 증명할 수 있다.
2. **약관은 버전 관리한다.** 약관이 바뀌면 새 버전을 추가하고 재동의를 받는다.
3. **역할(role)은 클라이언트가 바꿀 수 없다.** 컬럼 단위 권한으로 `nickname`, `display_name`, `avatar_url`만 수정 가능.
4. **구독 쓰기는 서버 전용.** 결제 웹훅이 secret 키로 갱신하고, 회원은 자기 구독 조회만 가능.
5. **결제 기록은 탈퇴해도 남긴다.** `subscriptions.user_id`는 `on delete set null`. 전자상거래법상 거래 기록 보존 기간(통상 5년)을 고려했다. 구체 기간은 전문가 확인이 필요하다.
6. **기본은 닫힘.** 자동 노출 OFF, 자동 RLS ON 설정과 맞춰 필요한 테이블·컬럼에만 `grant`한다.

## 5. 접근 권한 요약

| 테이블 | 비로그인 | 로그인 회원 | 관리자 |
|---|---|---|---|
| profiles | 없음 | 본인 조회·일부 컬럼 수정 | 전체 조회 |
| consent_documents | 조회 | 조회 | 조회 |
| user_consents | 없음 | 본인 조회·추가 | 전체 조회 |
| plans | 활성 요금제 조회 | 동일 | 동일 |
| subscriptions | 없음 | 본인 조회 | 전체 조회 |

## 6. 로그인 방식

- 1차: 이메일 + 구글
- 이어서: 카카오, 네이버 (각 개발자센터에서 앱 등록 필요. 네이버는 Supabase 기본 제공 대상이 아니라 별도 구현이 필요할 수 있음)

## 7. 가입 흐름

1. 가입 화면에서 필수(이용약관, 개인정보 수집) / 선택(마케팅 수신) 동의를 받는다.
2. 가입 완료 시 `profiles` 자동 생성 (트리거), 동의 내역을 `user_consents`에 기록.
3. 닉네임 설정 → 내 계정에서 변경 가능.

## 8. 탈퇴 처리 (구현 시 결정 필요)

- `profiles.deleted_at` 표시 후 개인정보 익명화, 서버(secret 키)에서 `auth.users` 삭제.
- 보존 의무가 있는 결제 기록은 유지.

## 9. 법무 체크 (전문가 검토 필요)

- 개인정보처리방침·이용약관을 회원 수집 기준으로 재작성 (현재 `privacy.html`은 회원 수집 전제가 아님)
- 마케팅 수신 동의는 별도 항목으로 분리 (정보통신망법)
- 상담DB를 제3자에게 제공하는 경우 별도 동의 + 금융 규제 검토
