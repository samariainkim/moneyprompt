## 2. CALC BUFF 공통 설계 원칙 [확정]
1. **역할 분리:** 계산기는 빠르게 이해하는 도구, AI 프롬프트는 깊이 확인하는 도구.
2. **핵심 입력 5개 이내.** 사용자가 약정서·규정을 꼼꼼히 분석해야 계산되는 구조를 만들지 않는다.
3. **간편 추정이라도 계산은 정확하게.** 지원하는 산식·날짜·정수 연산(BigInt, 원 미만 버림)은 엄밀히 구현한다. "간편"은 오류의 면책이 아니다.
4. **미반영 조건은 결과 바로 아래에 항상 표시한다.** (가정 칩 + 안내 박스)
5. **자동 기본값 금지:** 요율·기간 등 계약상 값은 사용자가 입력·선택한다. 대출 종류 등으로 요율을 추정하지 않는다.
6. **AI 프롬프트는 핵심 기능:** 입력값·산출값을 FACT로 전달, 미입력 정보는 "미입력"으로 명시하고 AI가 먼저 질문하게 한다. AI가 약정서·법령을 검증했다고 단정하지 않게 한다.
7. **결과는 세 질문에 답한다:** 얼마인가 / 왜 그 금액인가 / 무엇을 더 확인해야 하는가.
8. 환전수수료·ETF 비용·대출 이자 등 후속 계산기에도 동일 적용.

## 3. 대출 중도상환수수료 계산기 명세

### 3-1. 입력 (필수 5개, 추가 입력 없이 계산)
| # | 항목 | 형태 | 검증 |
|---|---|---|---|
| 1 | 중도상환 예정금액 | 숫자(원), 천단위 콤마 | 0 초과, 계산기 입력 범위 10조원 이하(운영 정책) |
| 2 | 대출 실행일 | 텍스트, 숫자만 연속 입력하면 `YYYY-MM-DD` 자동 정리 | 유효한 달력 날짜 |
| 3 | 상환 예정일 | 위와 동일 | 실행일 이상 |
| 4 | 수수료 부과기간 | 버튼 `1년/2년/3년/직접 입력(개월)` | **기본 선택 없음**, 직접 입력 1~36개월, 36개월 초과는 `unsupported`(AI 분석 안내) |
| 5 | 약정 수수료율 % | 숫자 | **기본값 없음**, 소수 둘째 자리까지, 0 허용(0원), 5.00% 초과는 "계산기 입력 범위" 안내로 차단 |

- 5.00%, 36개월, 10조원은 **서비스 운영상 입력 범위**이며 법정 상한·법정 부과기간이 아니다(문구에 "법정" 사용 금지). 값은 `loan-prepay.rules.v1.0.0.json`의 `limits`에서 조정.
- 제외: 대출 종류, 전액/일부 선택(금액으로 통합), 만기일, 대출잔액, 산정 방식 선택, 면제·감면, 연간 면제 한도. 이들은 AI 프롬프트의 "미확인 정보"로 전달.

### 3-2. 계산 정책
- 부과 종료일 `E = 실행일 + N개월` (달력 가산). **월말 규칙:** 대상 월에 같은 일자가 없으면 그 달의 말일 (예: 1/31 + 1개월 = 2/28 또는 2/29, 2/29 + 12개월 = 다음해 2/28).
- 전체 일수 `D_t = E − 실행일` (실제 달력 일수, 윤년 반영, 1,095일 고정 아님).
- 잔여 일수 `D_r = max(E − 상환일, 0)`.
- 수수료 `F = floor(P × 요율bps × D_r ÷ (10,000 × D_t))` — BigInt 정수 연산, 중간 반올림 없음.
- **간편 계산 명시적 가정:** 부과 종료일 당일 이후 수수료 0원(실제 약정의 경계일 처리와 다를 수 있음).
- 상환일 ≥ E: 수수료 0원 + "부과기간이 지난 시점" 설명, **상환일 비교 영역 숨김**.
- 면제·감면, 연간 한도, 금융사별 일수 포함 기준·원 단위 처리: 미반영(결과 아래 항상 안내).

### 3-3. 결과 화면 (기존 카드 구조·다크 테마·오렌지 포인트 유지)
금액 → 이유 → 실제 확인 사항의 3영역으로 압축한다.
1. 배지 `간편 추정` + 예상 수수료(큰 숫자)
2. **왜 이 금액일까요?** (부과기간 경과 시 **왜 0원으로 계산됐을까요?** + 종료일 안내) — 개념 설명과 산식 풀이
3. **실제 청구금액도 같을까요?** (경과 시 **실제로도 0원일까요?**) — "입력한 부과기간과 수수료율로 잔여기간 비례 방식을 적용한 예상 금액이에요. 실제 약정에서는 대출 만기, 수수료 산정기간, 면제·감면 조건 등에 따라 차이가 날 수 있어요." + 미반영 조건(면제·감면, 일부상환 한도, 상품별 산식) + "정확한 청구금액은 금융회사에서 확인해 주세요."
4. 접이식 `계산 내역 자세히 보기`(기본 닫힘): 금액, 요율, 부과기간, 기간 범위, 잔여/전체 일수, 적용 가정
5. 접이식 `상환 시점 비교`(기본 닫힘, **부과기간 안의 상환일에만 표시**): 현재 / +30일 / +90일(종료일 이전일 때만) / 종료일(0원, 간편 계산 가정). 필수 문구: "수수료만 비교한 결과예요. 상환을 미루는 동안 발생하는 대출이자는 포함되지 않았어요. 실제 유불리는 AI 심층분석에서 함께 확인해 보세요."
6. AI 심층분석 카드, 공유용 문구 복사

### 3-4. AI 심층분석 (메뉴 v2.0, 5개)
내 수수료 정확성 확인(검증) · 지금 갚기 vs 유지 비교(의사결정, 이자 절감 포함) · 대출 갈아타기 분석(대안 비교) · 수수료 면제·감면 확인(비용 확인) · 중도상환 전 체크리스트(실행). **기본 선택은 "내 수수료 정확성 확인" 1개.**
프롬프트 구조: 역할 → FACT(`[사용자 입력]` / `[계산기 산출]` / `[미확인 정보]` 구분) → VERIFY(독립 검산 포함) → SIMULATE(비교 메뉴 선택 시에만) → 요청 분석(선택 메뉴만) → 분석 규칙 → 답변 형식(핵심 요약 → 선택 분석 → 꼭 필요한 질문 최대 3개 → 다음 행동).
- 질문 규칙(고정 문구): "현재 정보만으로 설명할 수 있는 내용은 먼저 분석하세요. 개인별 정확한 계산에 반드시 필요한 정보만 최대 3개 질문하고, 정보가 부족한 계산만 보류하세요."
- 미확인 정보: 대출잔액, 대출 만기일, 대출금리, 상환방식, 수수료 산정 시작일·기준, 면제·감면 조건, 상품 종류
- 정확성 검증 질문에 "산정 시작일이 실행일과 다른 경우 / 만기가 부과기간보다 짧은 경우"를 포함. 상환 예정일이 오늘 이전이면 "과거 자료 분석과 현재 실행 판단 구분" 규칙을 추가.

### 3-5. 엔진 계약
- 파일: `calc/loan-prepay/` + `shared/loan-engine.js`(`LoanEngine`), 규칙·문구: `data/loan-prepay.rules.v1.0.0.json`, `.copy.json`, `.insights.json`, `.prompt.v1.0.0.json`. 기존 중개보수 코드(`Fee*`)는 수정하지 않는다.
- 결과 status: `success` | `invalid_input`(오류 코드: amount, date_order, period_missing, rate_missing, rate_format, rate_too_high 등). `period_ended` 플래그는 success + 0원.
- 규칙 JSON에는 정책값(금액 상한, 요율 상한, 비교 간격 30/90일, 개월 범위)만 두고 법령 수치는 두지 않는다. `status`는 검증 전까지 `pending`, `effective_from`·`verified_at`은 null 유지(임의 기입 금지).
- GA4: `calc_view/start/result/error/ai_generate/ai_copy/share` (calculator_id `loan-prepay`, category `loan`), 금액은 전송 금지.

### 3-6. 상태 관리 [확정 — 검증 문서 P0 반영]
- 다섯 입력(금액·실행일·상환일·부과기간·수수료율) 중 하나라도 바뀌면 **결과, AI 카드, 생성된 프롬프트, 공유 문구를 모두 숨기고** 다시 계산해야 갱신된다.
- AI 분석 항목 체크가 바뀌면 생성된 프롬프트를 숨기고 "선택한 분석 요청문 만들기"를 다시 누르게 한다(복사는 최신 생성본에서만 가능).
- 계산 오류가 나면 이전 결과를 남기지 않는다.

## 4. 테스트 (자동화 필수)
**수학(합성, 전체 1,095일·요율 1.0%·원 미만 버림)**
| 케이스 | 기대 |
|---|---|
| 1억, 잔여 730일 | 666,666 |
| 1억, 잔여 547일 | 499,543 |
| 1억, 잔여 0일 | 0 |
| 1,000만, 잔여 730일 | 66,666 |
| 요율 0% | 0 |
합성 일수 재현용 날짜: 실행 2020-03-01, 부과 3년(E=2023-03-01, 1,095일). 상환 2021-03-01(730일) / 2021-08-31(547일) / 2023-03-01(0일). **자동 테스트로 고정 완료** (`tests/loan-engine.test.js`, `tests/loan-prompt.test.js`)

**날짜 정책(추가)**
- 3년이 윤일을 포함하면 전체 1,096일 (예: 2023-01-01→2026-01-01)
- 월말 가산: 1/31+1개월, 8/31+6개월, 2/29+12개월, 윤년 2/29 실행 후 3년
- 부과종료일 경계: 상환일 = E−1일 / E / E+1일 (각각 1일분 수수료 / 0 / 0, 비교 영역 숨김)
- 상환일 = 실행일(잔여 = 전체)
- +30일/+90일이 E 이후인 경우 비교 행 생략

**입력·예외:** 상환일<실행일, 금액 0/음수/문자, 요율 미입력/소수 3자리/5% 초과, 부과기간 미선택, 직접 입력 0·37개월(unsupported).
**프롬프트:** 미입력 6항목 포함, 약정 검증 단정 금지 문구, 비교표는 `compare` 선택 시에만, E 이후 상환 시 SIMULATE 생략.
**화면:** 모바일 폭 입력, 접이식 기본 닫힘, 가정 칩·미반영 안내 항상 표시, 키보드 조작.
