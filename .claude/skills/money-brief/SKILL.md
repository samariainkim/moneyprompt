# MONEY BRIEF 한 호 만들기

사용자가 **"돈버프 카드뉴스를 제작해줘"**라고 하면 아래 순서로 진행한다. 이 순서는 NO.1~3호를 실제로 만들고 운영에 올리며 사용자와 합의한 방식이다.
먼저 읽을 것: `references/topic-selection.md`(주제), `references/fact-check.md`(검증), `references/copy-guide.md`(문구), `references/edition.md`(edition.json 형식). 사이트 반영은 `references/publish.md`, SNS는 `references/social.md`.

## 지켜야 할 약속 (사용자 규칙)
- **주제는 사용자가 고른다.** 먼저 후보를 리스트업해 보여 주고, 사용자가 하나를 정한 뒤에만 제작한다. 임의로 한 편을 정해 만들지 않는다.
- **최종 시안은 사용자가 검수한다.** 사용자가 확정한 문구·숫자는 임의로 고치지 않는다(오탈자도 지시가 있을 때만).
- **`main` 병합은 사용자가 "머지해"라고 명시할 때만.** PR 도 사용자가 요청하기 전에는 만들지 않는다(병합 요청 = PR 생성·병합 허가).
- 사실 확인이 안 된 내용은 카드에 쓰지 않는다. 확인하지 못한 항목은 **숨기지 말고 보고서와 보고 메시지에 적는다.**
- 특정 종목·금융상품·금융사 추천, 수익 보장, 투자 권유로 읽히는 표현은 쓰지 않는다. 법률·세무 판단은 하지 않고 "최종 확인은 공식 기관·전문가"로 안내한다.
- 사용자의 이메일 등 개인정보를 게시글·외부 요청에 넣지 않는다. 한국어로 소통한다. 작업 파일(시안·임시 파일)은 scratchpad 에 두고 저장소에는 결과물만 남긴다.
- 새 메뉴는 늘리지 않는다(헤더 `MONEY BRIEF` 메뉴와 메인 배너는 이미 있다).

## 절차

### 1. 주제 후보 리스트업 → 사용자 선택 (제작 금지)
`references/topic-selection.md` 대로 이번 시기 이슈를 조사해 후보 6~8개를 **표**로 보여 준다: 주제 / 형식(뉴스·정보·체크리스트) / 연결 도구(계산기 또는 프롬프트) / 왜 지금인가 / 연계성·최신성·관심도 / 검증 난이도·주의. 추천 2편과 이유, 발행 전 필요한 선작업(원문 확인, 도메인 허용 등)을 적고 **사용자가 고르기를 기다린다.**
- 돈버프 연계: 계산기(`calc/`: 대출 중도상환, 환전수수료, 부동산 중개보수, 증권사 수수료)와 프롬프트(`prompt/index.html` 의 `idx`·`title`, 172개·7개 분류)를 실제로 확인해서 짝을 짓는다. 연결할 도구가 없는 주제는 장기 과제로 표시한다.

### 2. 1차 자료 원문 확인 (`references/fact-check.md`, `references/sources.md`)
- 근거는 정부·감독기관·금융사 공시 같은 **1차 자료 원문**만. 검색 결과 요약·블로그는 단서일 뿐이다(원문을 열어 보니 다른 내용이었던 사례가 있었다).
- **귀속 연도·시행일·기준일**을 구분한다(예: 올해 11월에 준비하는 연말정산은 "2026년 귀속", 검색에 많이 나오는 건 작년 자료).
- 막힌 도메인은 우회하지 말고 `update_environment` 로 **최소 호스트만 허용 요청**한다(사용자 승인 화면이 뜬다).
- 1차 자료 단독 근거인 항목, 작년 기준 수치 등 **교차 확인이 안 된 항목은 목록으로 남긴다.**

### 3. 숫자는 계산 엔진에서만
카드 속 숫자(수수료·환전액·절감액 등)는 손으로 옮겨 적지 않는다. `edition.json` 의 `calc` 에 입력값을 적고 본문에서 `{{loan_new.fee_krw|won}}` 처럼 가져온다(`scripts/engine.mjs` 가 `calc/shared/*-engine.js` 로 계산). 빌드 때 `scripts/crosscheck.py` 가 **엔진과 다른 방식으로 독립 검산**하고 불일치하면 멈춘다. 정책 수치(요율·한도 등)는 1차 자료 값을 쓰고 검증 보고서에 근거를 적는다.
- 환율 카드는 **발행 직전**에 다시 빌드한다(기준일이 지나면 숫자가 바뀐다). `calc/data/fx/rates.json` 이 최신일 때 `build_cards.py` 만 다시 돌리면 된다.

### 4. edition.json 작성 → 카드 7장 빌드
작업 폴더(scratchpad 아래 `brief-NNN/`)에 `edition.json` 을 만든다(`assets/examples/` 의 3편이 완성 예시, 형식은 `references/edition.md`). 7장 구성: ① 표지 ② 무엇이 달라졌나/상황 ③ 누구에게·무엇이 핵심 ④⑤ 숫자·계산 ⑥ 저장용 체크리스트 ⑦ **CTA(계산기·프롬프트·외부 링크로 이어지는 카드)**.
```bash
python3 .claude/skills/money-brief/scripts/check_edition.py <작업폴더>   # 점검(금지 표현·면책·출처·숫자)
python3 .claude/skills/money-brief/scripts/build_cards.py  <작업폴더>   # 카드 PNG 7장 + sheet.jpg
```
빌드는 계산·독립 검산, 글꼴 로드, **글자 넘침 자동 점검**까지 하고 하나라도 어긋나면 멈춘다. 결과 이미지는 직접 열어 눈으로 확인한다.

### 5. 검증 보고서 작성
`assets/verify-report.template.md` 로 `verify-<주제>.md` 를 쓴다: 1차 자료 목록(주소·확인 내용), 카드별 문장 검증표(근거·상태), 계산 숫자(엔진=독립 검산), **일부러 뺀 내용과 이유**, 표현 점검, **확인하지 못한 것**. 

### 6. 사용자에게 보고 (최종 시안 한 번에)
`SendUserFile` 로 `sheet.jpg` + 카드 7장 + 검증 보고서를 보내고, 한 메시지에 담는다: 카드 구성 표, 검증 방식, **발행 전 운영자가 확인할 것**(교차 확인 안 된 수치·작년 기준 수치 등), 다음 단계. 카드 전체 문구를 메시지에 반복하지 않는다.

### 7. 수정 요청 → 해당 카드만
`edition.json` 의 해당 카드만 고쳐 다시 빌드한다(확정된 카드는 건드리지 않는다). 사실이 바뀌는 수정이면 검증 보고서도 갱신한다.

### 8. 사이트 반영 (`references/publish.md`)
사용자가 "확정/반영"이라고 하면: 최신 `main` 에서 브랜치를 판다 → `publish.py <작업폴더>` (이미지 JPG 변환 + `web/redesign/data/brief.json` 갱신) → `node web/scripts/sync-static.mjs` → 시험(`scripts/test_brief_smoke.js` + 기존 회귀) → 커밋·푸시 → 테스트 환경에서 사용자 확인.
**호를 추가해도 페이지·메인 배너·지난 호 목록은 `brief.json` 에서 자동으로 따라간다**(코드 수정 없음). 호 번호는 발행 순서이고 가장 큰 번호가 최신호다.

### 9. "머지해" → 운영 반영
사용자가 "머지해"라고 하면 PR 을 만들고(`gh api` REST, GraphQL 은 막혀 있다) 병합한다. 병합 뒤 Vercel 운영 배포 완료를 기다렸다가 `curl`/`NODE_USE_ENV_PROXY=1 node web/scripts/verify-routes.mjs https://donbuff.com` 으로 `/brief/`·카드 이미지·메인 배너를 운영에서 직접 확인하고 결과를 보고한다.

### 10. 인스타그램·쓰레드 자료 (`references/social.md`)
호별 이미지 ZIP(카드 7장 1080×1350 + 게시글)와 게시글을 만든다: `assets/caption.template.md` 를 보고 `caption_instagram.txt`·`caption_threads.txt` 를 쓰고 `scripts/export_social.py <작업폴더>` 로 묶는다(길이·개인정보·출처 점검 포함). 게시 순서는 호 번호 순.

## 알려진 함정 (실제로 겪은 것)
- **검색 요약 ≠ 원문.** 금융투자협회 페이지가 "해외주식 환전 비용" 설명처럼 요약됐지만 원문은 FX마진거래(파생) 안내였다. 인용 전에 반드시 원문을 연다.
- **귀속 연도 혼동.** 검색에 나오는 연말정산 안내의 상당수는 작년(2025년 귀속)이다. 올해 정산 기준 자료를 따로 찾는다.
- **블로그 한 곳의 "뉴스".** 단일 블로그 출처의 이슈(예: 증권사 이벤트 종료·금감원 점검)는 근거로 쓰지 않는다 → 뉴스형 대신 정보형으로 구성했다.
- **정부 카드뉴스 이미지·문장은 복제하지 않는다**(공공누리 조건: 변경금지·상업적 이용금지 등). 사실만 새로 구성하고 출처를 적는다.
- Node 의 `fetch` 는 이 환경의 프록시를 못 쓴다 → `curl` 또는 `NODE_USE_ENV_PROXY=1`.
- Stop 훅이 "unpushed commits" 를 반복해도 `git ls-remote origin <브랜치>` 가 로컬 HEAD 와 같으면 이미 푸시된 것이다(추적 설정 문제).
- 테스트 주소(vercel.app)는 이 환경에서 접속이 막혀 있다 → 사용자에게 Vercel 배포 페이지에서 열어 보도록 안내한다. 운영(donbuff.com)은 `curl` 로 확인 가능.
- 카드 이미지 레이아웃은 **글자 수에 민감**하다. 빌드의 넘침 점검이 실패하면 글을 줄인다(글자 크기를 줄이지 않는다).

## 하지 않는 것
- 사용자가 고르기 전 주제 확정·제작, 사용자 승인 전 병합·PR, 예약 실행 등록
- 원문을 확인하지 못한 숫자·사실을 카드에 쓰기, 엔진 값을 손으로 바꿔 적기
- 사용자가 확정한 카드 문구·숫자의 임의 수정, 확인 못 한 항목을 보고에서 빼기
- 저장소에 임시 파일·시안을 남기기(작업은 scratchpad)
