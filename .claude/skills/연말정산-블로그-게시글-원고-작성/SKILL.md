# 연말정산 블로그 게시글 원고 작성

사용자가 **주제**를 주면 `references/style-guide.md`(문체·구성·톤)와 `references/sample-01.md`(승인된 1편 완성본)를 먼저 읽고, 그 느낌과 형식으로 쓴다.
사실 확인은 `references/fact-rules.md`, 사이트 연결은 `references/site-links.md`를 따른다.

## 진행 순서
1. **주제·편 번호 확인.** 주제는 사용자가 정한다. 연재 목록은 `web/redesign/pages/yearend.html` 의 `ye-posts`에 있다(1편 발행 — 2편 "2026 귀속 달라진 공제 총정리", 3편 "12월 31일 전에 확인해야 할 7가지"는 발행 예정이며 제목은 사용자가 준 것을 따른다).
2. **자료 확인.** 1차 자료(국세청·기획재정부·국가법령정보센터) 원문을 직접 열어 확인한다. 못 연 것은 쓰지 않거나 "확인 필요"로 표시한다. 웹 검색 전에 사용자에게 허용 여부를 묻는다(앞서 사용자가 검색 호출을 중단시킨 적이 있다). 사용자가 자료를 주면 그것을 우선 근거로 쓴다.
3. **원고 작성.** 스타일 가이드의 구성(도입 → 핵심 3가지 → 본문 소제목 번호 → 사례 → 체크리스트 → 주의 → 돈버프 안내 → FAQ → 마무리 → 출처·면책 → 해시태그).
4. **사실 확인표를 원고와 함께 준다.** 원고에 쓴 날짜·숫자·요건마다 근거 자료(이름·기준일)를 적고, 단일 출처·미확인은 표시한다. 사용자가 법령 출처를 최종 검증한다.
5. **파일로 저장.** 원고는 사용자가 복사해 네이버 블로그에 붙일 수 있게 `.md` 로 스크래치패드에 저장하고 사용자에게 전달한다(이미지·표 위치는 `[이미지: …]`로 표시). 저장소에 커밋하지 않는다(요청 시에만).
6. **발행 후:** 사용자가 URL을 주면 허브 `ye-posts` 의 해당 편을 "발행 ↗" 링크로 바꾼다(`site-links.md`).

## 반드시 지킬 것
- 공제 가능 여부·환급액을 **단정하지 않는다.** "확인해 볼 항목", "요건을 확인하세요"로 쓴다. 특정 금융상품·금융사 추천 금지. 세무 상담이 아니라는 면책 문구를 마지막에 넣는다.
- 귀속 연도(2026년 귀속, 2027년 1월 정산)와 기준일을 명시한다. 작년 한도·요건을 올해 값처럼 쓰지 않는다. 확정 전 세제 개편안은 현행처럼 쓰지 않는다.
- 숫자(공제율·한도·금액)는 출처를 확인했을 때만, 출처·기준 연도와 함께 쓴다. 의심되면 숫자를 빼고 구조만 설명한다(1편처럼).
- 1편 시점의 서비스 공개 일정("12월 초 공개 목표")은 바뀔 수 있다. 서비스 상태는 쓰기 전에 현재 상태(운영 오픈 여부)를 사용자에게 확인한다. 미오픈이면 "준비 중", 오픈이면 링크로 안내한다.
- 환급·절세를 위해 불필요한 소비를 권하지 않는다(1편의 핵심 태도: "환급금을 늘리는 것보다 받을 수 있는 공제를 놓치지 않는 것").
- 사용자의 개인정보·계정 정보를 원고에 넣지 않는다.
